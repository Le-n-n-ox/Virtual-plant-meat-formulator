# Mock API

The frontend develops against a mocked FastAPI service until the backend routers
exist. MSW (Mock Service Worker) intercepts same-origin `/api/*` requests in the
browser.

## Enabling

```sh
NEXT_PUBLIC_USE_MOCKS=true npm run dev
```

`MockProvider` (mounted in `src/app/layout.tsx`) starts the worker before the
first query and renders a persistent **Mock data** banner. It also gates
rendering until the worker is ready, so no query hits a real backend by mistake.

> Keep `NEXT_PUBLIC_API_BASE_URL` unset (or empty) while mocking. A non-empty
> base URL points the client at another origin, which the service worker cannot
> intercept.

## Coverage

Every endpoint in `docs/frontend-guide.md` §6 has a handler in
`src/mocks/handlers.ts`: auth, ingredients, formulations (+ versions, validate),
jobs (+ cancel, result, SSE stream), nutrition, candidates (+ promote), compare,
models, exports and health.

The job stream at `GET /api/jobs/:id/events` replays scripted events over SSE,
including measurable `completed`/`total` progress for optimization runs and
indeterminate stages for texture runs.

## Fixtures

`src/mocks/fixtures/` holds synthetic records only. Every ingredient source is
`Mock data — not real`, every nutrient is flagged `estimated`, and ids carry a
`mock-` prefix. Never present these numbers as measured composition or texture.

The demo workspace fixtures in `fixtures/ingredients.ts` are separate: they carry
no nutrient values at all and exist only to drive the editor and 3D scene.

## Service worker

`public/mockServiceWorker.js` is generated by MSW. Regenerate it after upgrading
MSW:

```sh
npx msw init public/
```
