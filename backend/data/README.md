# Data acquisition and readiness

This folder is for source files and generated imports. Keep original files unchanged, record their version and retrieval date, and retain row/page references for every imported value. Never convert a missing value to zero. A dataset must not be promoted into the product catalogue until its units, food identity, preparation state, provenance, and reuse rights have been reviewed.

## What Python packages can and cannot provide

Python packages do not supply the evidence itself. `pandas` and `httpx` can work with tabular/API data, and the source-specific importers in `app/ingestion/` normalize files already acquired. Open literature now supports development of a no-lab, research-only HME estimator. The estimator has not yet been implemented or evaluated in this project, and the sources do not establish accuracy for Kenyan whole-food formulations. Imported values remain review candidates with source IDs, row references, units, methods, and licence status.

## Remaining inputs before production data can be activated

1. If the project later becomes commercial, obtain FAO permission for KFCT reuse before commercial distribution.
2. Structure the recipe-book inventory into ingredient quantities, preparation steps, and nutrient fields, reviewing table alignment and rotated pages against the PDF. The code crosswalk is reconciled: 140 shared recipe IDs, book-only 15050 and 15135 without nutrient values, workbook-only 15021 (`Hard boiled eggs`), distinct 15066 rice/stew variants, and appendix-only 15083 whose printed energy/proximate values match the workbook. Never fill missing nutrients with zero. The original workbook's copyright notice permits non-commercial research with acknowledgement; contact FAO for resale or other commercial use rights.
3. Texture evidence now supports a literature-based exploratory estimator without a lab. Keep HME, low-moisture extrusion, and mechanical elongation separate; preserve entire source groups for evaluation; and show evidence coverage and uncertainty. The available HME sources still do not validate accuracy for Kenyan whole-food formulations. See `texture_data_readiness.md` for the model boundary and available evidence. Project-owned measurements would be needed only to claim local experimental validation.
4. The official KAMIS Excel export is available, but a current Nairobi Wakulima row and reuse terms remain unverified. Verify both before enabling cost optimization. Capture directly observed or quoted prices in `templates/market_price_observations.csv`, retain the original price string and source date, and convert to KES/kg only when both unit and currency are explicit. Do not infer prices from nutrient data or silently substitute another Nairobi market.
5. All FAO amino-acid patterns are available in `reference/fao_amino_acid_patterns_2013.yaml`, with no default chosen. Expert review is needed only before selecting a user-facing default. Do not report DIAAS without amino-acid-specific ileal digestibility data.

Raw downloads and generated imports are ignored by Git. The small FoodML CSV is a specifically attributed CC BY 4.0 research artifact tracked in `reference/`; other licensed or large raw files stay local and should use access-controlled storage/DVC only after rights review.

## Project-owned measurement templates

`templates/formulation_components.csv`, `templates/texture_measurements.csv`, and `templates/market_price_observations.csv` are header-only collection templates. Link each component row and each per-metric specimen measurement through `formulation_id`/`sample_id`; record actual measured or quoted values with source, methods, units, date, and provenance. Do not fill them with model estimates or inferred prices. Price records need one row per market observation. Keep cost features disabled until price-source reuse rights and matching coverage are confirmed.

To prepare the downloaded CSIRO CSVs for local analysis, run `python -m app.ingestion.import_csiro_texture` from `backend/`. The generated JSONL is ignored by Git, and every record carries the dataset citation, source file/row, and CC BY-NC-SA 4.0 restriction. The raw files are available from the [CSIRO collection](https://data.csiro.au/collection/csiro:73387).

To regenerate the KFCT review import, run `python -m app.ingestion.import_kfct_workbook` from `backend/`. By default it reads the downloaded workbook in `raw/` and writes an ignored JSONL candidate file and summary in `processed/`. The importer uses the Python standard library and preserves workbook row references, nutrient units, source text, non-numeric flags, statistics, sample counts, and missing-value columns.

To regenerate the recipe-book text inventory, install/use `pypdf` and `fontTools`, then run `python -m app.ingestion.import_kfct_recipe_book` from `backend/`. For an ephemeral environment, `uv run --no-project --with pypdf --with fonttools python -m app.ingestion.import_kfct_recipe_book` avoids changing project dependencies. It writes an ignored JSONL inventory, count/reconciliation summary, and extracted text. This remains a review artifact; it does not parse recipe ingredients or promote nutrient estimates into structured values.

To regenerate the KU Leuven high-moisture soy extrusion candidate import, run `python -m app.ingestion.import_kuleuven_hme` from `backend/`. It uses the standard-library XLSX reader already used by the KFCT importer and writes ignored JSONL plus a summary. The import preserves individual measurement rows and workbook row numbers; it does not pair measurements from different texture columns because the source does not supply specimen IDs.

To regenerate the FoodML literature sample import, run `python -m app.ingestion.import_foodml_texture_2023` from `backend/`. It reads the authors' downloaded CSV and writes ignored JSONL plus a summary. Each record preserves the original study/group identifiers, and the importer tags mechanical elongation separately from HME.

The FoodML importer also reads `data/reference/foodml_ferawati_2021_crosswalk.csv` and enriches the 30 Ferawati-derived rows with Tables A3/A4 process settings without adding duplicate records. The summary records the inferred sample mapping, target-unit factor, replication limits, and unresolved moisture discrepancy.

To regenerate the Kantanen 2022, Knaapila 2024, and Jeon 2023 literature imports, run `python -m app.ingestion.import_kantanen_hme_2022`, `python -m app.ingestion.import_knaapila_hme_2024`, and `python -m app.ingestion.import_jeon_full_fat_soy_hme_2023` from `backend/`. Each reads a tracked, source-cited transcription in `reference/` and writes ignored JSONL plus a summary. The Knaapila importer retains table values as reported but does not assign missing mechanical units or rescale WAC; those fields are not training targets until their units are reconciled. The Jeon importer retains its single fixed HME process and table-reported metrics as comparative evidence.

To regenerate the Mektun & Kijroongrojana 2026 mung-bean HME import, run `python -m app.ingestion.import_mektun_mungbean_wg_hme_2026` from `backend/`. It writes nine published condition summaries from the tracked CSV. Keep the imported means, standard deviations, and n=10 texture measurement counts distinct from the triplicate center-condition extrusion runs. Do not execute the Table 5 equation transcription until it is visually verified against the PDF.

To regenerate the Bulgaru et al. 2025 HME analog import, run `python -m app.ingestion.import_bulgaru_soryz_hme_2025` from `backend/`. It writes eight condition-level Table 2 summaries, including PPI controls and soryz, chickpea, and hazelnut-meal blends. Preserve the source's missing extrusion-batch count and moisture-basis ambiguity; do not treat n=12 TPA readings as extrusion batches.
